# 79 · 카카오 로그인: 서버는 성공하는데 앱이 로그인 화면에 남던 문제

빌드된 앱(TestFlight)에서 카카오 로그인을 하면 아무 일도 없던 것처럼 로그인 화면으로 돌아오던 건. 데이터 유실로 오해되기 쉬운 증상이라(커플 연결 화면·로그인 화면만 보임) 이틀에 걸쳐 원인을 추적했다.

## 진단 과정

서버에 톰캣 접속 기록을 임시로 켜고 실제 로그인을 시도하게 해 단계별로 좁혔다.

```
01:12:38  GET /api/auth/kakao/callback?code=...&state=today://auth  → 302   ← 서버 로그인 성공
01:12:44  (재시도)                                                  → 302   ← 또 성공
01:13:10  (재시도)                                                  → 302   ← 또 성공
이후     토큰을 단 요청 0건. DELETE /api/push-tokens 401 수십 건만 반복.
```

- 콜백 실패 로그 0건, 새 계정 생성 0건 → 계정 매칭까지 전부 정상.
- 즉 서버가 `today://auth?token=...` 으로 302를 보냈는데 **앱이 그 토큰을 받지 못했다.**

## 원인

카카오 인가가 **카카오톡 앱을 경유**하면 마지막 리다이렉트가 앱 안의 인증 세션(ASWebAuthenticationSession) 밖 — 사파리 — 에서 일어난다. 세션은 dismiss로 끝나고, 기존 코드는 dismiss를 "사용자 취소"로 취급해 조용히 로그인 화면에 남았다. 서버는 성공했는데 앱만 모르는 상태.

부수 발견 2건:
- 8/14 Apple 로그인으로 생긴 빈 계정은 이 문제를 우회하려던 흔적으로 보인다(Apple은 네이티브 로그인이라 이 경로를 안 탄다). 그 세션(30일 토큰)이 남아 "커플 연결 화면"이 떴던 것.
- 로그아웃 중 푸시 토큰 해제가 401을 받으면 전역 401 처리가 다시 로그아웃을 불러 **무한 반복**(접속 기록의 DELETE 401 수십 건).

## 변경

- **딥링크를 세션을 열기 전부터 구독**하고 세션 결과와 경주시킨다. 어느 쪽으로 토큰이 오든 받고, 딥링크가 이기면 남은 인증 창을 닫는다. dismiss 후 4초까지 늦게 오는 링크도 기다린다.
- 앱이 종료된 상태에서 `today://auth?token=` 링크로 켜지는 경우도 루트 레이아웃에서 받아 세션을 연다.
- 소셜 로그인 시작 시 **옛 세션을 먼저 비운다**(계정을 갈아탈 때 이전 계정 화면이 남지 않게).
- 401 로그아웃 무한 반복 차단(토큰이 이미 없으면 로그아웃 재호출 안 함).
- 서버: 카카오 콜백 실패를 로그로 남김(전에는 조용히 302 error 리다이렉트만 했다), 톰캣 접속 기록 활성화.
